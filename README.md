# 时间账本

记录「时间花在哪」的小应用。电脑和手机用同一套页面，数据存在各自本机，通过**自动同步**或**导出 / 导入**保持一致。

一级分类用来出图表（工作 / 学习 / 生活 / 运动 / 休息），二级标签记录具体做了什么（写代码 / 开会 / 阅读……）。

## 打开方式

### 电脑（推荐）

双击 **`启动.cmd`**。会起一个本地服务并自动打开浏览器。

> 也可以直接双击 `index.html`，但本地文件模式（`file://`）下既没有同步服务，浏览器对 localStorage 的持久化也不如 http 可靠。

### 手机

`启动.cmd` 默认**只监听本机**，手机是连不上的——这是有意的，理由见下面「局域网访问」。

手机上有两条路：

- **Gist 模式**（推荐）：不需要电脑开机，手机用流量也能同步，见「Gist 模式」
- **局域网**：只在自己家的 WiFi 里值得用，步骤和风险见「局域网访问（可选）」

---

## 局域网访问（可选，默认关闭）

### 为什么默认关着

`/api/sync` **没有密码**。服务一旦监听 `0.0.0.0`，同网络的任何人只要知道 `http://<你的IP>:5180`，就能用浏览器直接读走、甚至改掉你全部的时间记录。

校园网、公司网、咖啡厅 WiFi 都是成百上千人的大内网，把自己的服务放上去等于公开。**流量费不了多少，安全上得不偿失。**

所以默认 `serve.mjs` 只绑 `127.0.0.1`，只有本机能访问，连防火墙都不用管。

### 确实想用的时候

前提：**在自己家的 WiFi**，或者手机热点这种只有你自己的网络。

1. 用 `--lan` 参数启动：

   ```bash
   node serve.mjs --lan
   ```

   窗口会打印手机可用的地址，并给出安全警告。

2. 放行防火墙：双击 `放行防火墙.cmd`，UAC 点「是」
3. 手机连同一个 WiFi，打开窗口里打印的地址
4. 桥接完把手机加进主屏

**用完记得关掉**：`serve.mjs` 窗口按 Ctrl+C，或者改回不带 `--lan` 的启动方式。防火墙规则也可以随时删除。

### 手机还是打不开

按顺序看：

| 现象 | 原因 |
|---|---|
| 窗口里根本没打印「手机：」那一行 | 忘了加 `--lan`，或者电脑没连 WiFi |
| 打印了地址但连不上 | 防火墙没放行 |
| 电脑自己 `localhost:5180` 正常，手机一直转圈 | 校园网 / 公司网的 **AP 隔离**，两台设备互相看不见 |
| 昨天能用今天不能 | IP 变了，DHCP 重新分配过，看启动窗口打印的新地址 |

遇到 AP 隔离，可以用**手机热点**绕开：手机开个人热点 → 电脑连上 → 用 `--lan` 重启服务 → 看新地址（通常是 `192.168.43.x`）。

不过更省事的还是直接用 **Gist 模式**，不用管网络、不用电脑开着、也不暴露任何端口。

## 自动同步

设置页 → 自动同步，三选一：

| 模式 | 适用场景 | 需要什么 |
|---|---|---|
| 关闭 | 只在一台设备用 | 无 |
| **局域网** | 可信的家庭 WiFi 内 | `node serve.mjs --lan` + 放行防火墙 |
| **Gist** | 任何网络，包括校园网/流量 | 一个 GitHub Token |

### 局域网模式

用 `--lan` 启动服务后，手机连同一 WiFi 打开同一个地址，**两端各自打开页面就会自动互相同步**，不用点任何按钮。

- 同步数据存在电脑上的 `data/sync-state.json`
- 地址栏可以留空（表示用当前页面的地址），也可以填 `http://192.168.1.10:5180` 这样的具体地址
- 服务没开或不在同一网络时会显示"同步失败"，重新连上后自动恢复
- **不要把 `--lan` 开在校园网 / 公司网 / 公共 WiFi 上**，原因见前面的「局域网访问」

### Gist 模式

把数据存到 GitHub 上的一个 **secret gist**，不依赖局域网，手机用流量也能同步。

**先明确它不是"私有"的**：secret gist 不会出现在你的 gist 列表和 GitHub 搜索结果里，但**任何拿到链接的人不需要登录就能读**。这是 GitHub 对 secret gist 的定义，不是加密。链接里的 gist ID 是 32 位随机串，猜不到，但也别主动公开它。

### 申请 Token

1. 打开 <https://github.com/settings/tokens>
2. 选 **Tokens (classic)** → **Generate new token (classic)**
3. Note 随便填（比如 `time-tally`），Expiration 选 90 天或 No expiration
4. 权限**只勾 `gist`**，其它全部不勾
5. 生成后立刻复制（**只显示这一次**，关掉就看不到）

### 配置

1. 把 Token 填进设置页，Gist ID **留空**
2. 点「立即同步」——会通过 API 自动创建一个 secret gist，里面只有一个 `time-tally.json`
3. 另一台设备填**同一个 Token**，然后把第一台设备上的 Gist ID 抄过去

> Token 只存在这台设备的浏览器里，不会写进导出文件，也不会发给除 `api.github.com` 之外的任何地方。
>
> classic token 如果**一年没有使用**，GitHub 会自动删除它，届时重新生成一个填进去即可。

### 限额（2026-11 核实）

| 项目 | 限制 |
|---|---|
| Gist 数量 | 没有公开的硬性上限，个人使用远碰不到 |
| 单个文件 | 100 MB（网页界面手工上传上限 25 MB） |
| API 返回的单文件内容 | 最多 1 MB，超出要走 `raw_url`（程序已处理） |
| 超过 10 MB 的文件 | 需要 clone，程序不支持——但时间记录正常一年也就几百 KB |
| REST API 请求数 | 认证用户 **5000 次 / 小时**（所有 token 共享这个额度） |
| fine-grained token 数量 | 每个账号最多 50 个 |
| classic token 数量 | 无明确上限，一年不用会被自动删除 |

这个应用同步一次最多 2 个请求（读 + 写），**内容没变时只读不写**，所以每分钟 1 次、两台设备约 120 次/小时，离 5000 很远。

### Token 类型

- **classic token**：勾 `gist` 即可，最省事，推荐
- **fine-grained token**：也能用，但要在 **Account permissions → Gists** 里设为 **Read and write**；设成只读会同步失败

> Token 只存在这台设备的浏览器里，不会写进导出文件，也不会发给除 GitHub 之外的任何地方。

### 同步规则

- 同一条记录（相同 id）以**修改时间较新的**为准
- 分类按**名字**对齐——两端都叫「工作」的分类不会变成两个
- 删除会同步：在 A 端删掉的记录，B 端同步后也会消失
- 「清空所有记录」是标记删除再同步，所以其他设备会一起清空（分类保留）
- 正在计时的记录会按当前时刻封口后同步，另一台设备看到的是"截至刚才已记录多久"，停止后会更新为最终时长

### 什么时候会自动同步

- 改动数据后约 4 秒
- 每 60 秒轮询一次（页面在前台时）
- 切回页面时（超过 20 秒没同步）
- 设置页的「立即同步」按钮

顶栏右上角的小圆点表示状态：绿色已同步、蓝色同步中、红色失败、灰色未同步。

## 手动同步

没有开启自动同步、或想额外备份时，仍可以用文件搬运：

```
电脑：导出 time-tally-20260510-2130.json  ──►  发到手机（微信 / QQ / 网盘 / 隔空投送）
手机：导入这个文件                          ──►  合并
```

合并规则与自动同步一致。导入报告会说新增了几条、更新了几条。

> 部署到 GitHub Pages 后没有 `/api/sync` 接口，局域网模式用不了，请改用 **Gist 模式**或手动导入导出。

## 主界面

| 位置 | 功能 |
|---|---|
| 正中大圆按钮 | **开始** → 选一个二级标签立刻计时；计时中变红，点一下**停止** |
| 大按钮下方三个入口 | **补记** / **导出** / **导入** |
| 常用标签 | 最近用过的 5 个二级标签，点一下直接开始；计时中点另一个就是**切段** |
| 今日记录 | 点任意一条可以改时间、改标签、加备注或删除；左右箭头翻看前几天 |
| 底部 记录 / 统计 / 设置 | 主界面、图表、分类与同步 |

切段的意思是：正在记「开会」时点「写代码」，会以同一秒结束上一段并开始下一段，不留缝隙也不重叠。

补记里给了 15 / 30 / 45 / 60 / 90 分钟的快捷按钮，跨零点会自动按跨天处理。

## 数据安全

- 数据存在各设备的浏览器里；开了自动同步才会在设备之间流转
- 局域网模式的数据存在电脑的 `data/sync-state.json`，这个目录不会提交到 git
- 清理浏览器数据 / 换设备会丢数据，仍建议偶尔导出备份
- 超过 7 天没导出，设置页会提醒

## 开发

无构建步骤，改完 `index.html` 刷新即可。

```bash
node test-logic.cjs   # 20 项：区间裁剪、跨天切分、聚合、合并去重
node test-sync.mjs    # 17 项：版本推进、409 冲突、持久化、目录保护
```

同步接口：

```
GET  /api/sync?t=<时间戳>      → { rev, updatedAt, payload }
POST /api/sync                 → { since, payload }；since 与当前 rev 不符返回 409
GET  /api/health               → { ok, app, rev }
```

服务端只负责存储和版本号，合并逻辑在客户端。客户端先拉取合并、再带着 `since` 推送；

版本对不上时（另一个设备刚提交过）服务端返回 409，客户端重新拉取合并后重试，最多 3 次。
